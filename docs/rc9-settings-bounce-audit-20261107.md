# 设置 / 关于顶部回弹复核

日期：2026-11-07。代码基线 `8da710271fb20399aeb5faab9c58aeaf7219ebe0`。
用户观察：低电量页回弹自然，设置页顶部回弹不自然，怀疑新增菜单导致。

## 源码证据

对照固定参考而非未经重新核实的远端最新版：

- 官方 RootHide `9617d75f476423fdfd33477299c8a1349eb6f375`。
- ZQBB RootHide `7e14aa6155ce867e9052a88a8c17c632f4c30d77`。
- RC9 现有低电量页 `DOLowPowerScheduleController`。

| 项目 | 设置 / 关于 | 低电量页 |
| --- | --- | --- |
| 列表实现 | `DOPSListController` / 私有 Preferences | `UIViewController` 自建 `UITableView` |
| 顶部处理 | 保留 Preferences / UIKit 原有自动 inset | 表格约束在独立标题下面，关闭自动 inset |
| 回弹参数 | 当前没有覆写原生回弹与高度估算参数 | 显式开启垂直回弹 |
| 每行显示回调 | 原先每次遍历并重排全部玻璃背景 | 不在每行显示时重排背景 |
| 菜单添加 | 添加 PSSpecifier 数据与动作，未直接设置回弹参数 | 独立数据源 |

固定官方和 ZQBB 的 `DOPSListController.m` 在相关布局上相同，
没有 RC9 的分组玻璃渲染。RC9 当前在官方列表 frame 基础上加
frame 相等判断及 24pt 底部滚动余量，顶部 inset 继续交给原生实现。
本轮不再修改这部分。

“菜单行增加”只能说明内容长度、复用和显示回调的分布改变，
不能仅凭这一点确认回弹根因。设置标题由 `headerCellClass` 创建为
分组表头，不是普通第一行；玻璃代码中根据可见第一行类名跳过标题的
判断也不能据此认定为这次问题的原因。

## 本轮窄范围修正

旧 `willDisplayCell` 在每次显示任意一行时，都会对字典中的每个
玻璃 view 调用 `sendSubviewToBack:`，即便它们已经全部在内容后面。
多个玻璃 view 之间还会反复交换前后顺序。这是可从源码确认的额外操作；
低电量页没有对应的无条件循环。

在共用列表父类增加层级检查：

1. 遍历当前直接子 view，只检查所有已挂载玻璃是否连续位于内容后方。
2. 顺序已经正确时，不重排任何 view。
3. 确有内容被插入玻璃下方时，执行既有置底修正一次。
4. 不重排其他表格或已经移除的玻璃，不改变内容 view 的相对顺序。

设置 / 关于共享此检查。继续保留每行前景样式处理、背景初始化和真实遮挡
修正，避免简单删除置底保护后再次出现文字被玻璃采样而模糊的问题。

本轮不删除剩余菜单，不替换 Preferences，不增减顶部 / 底部 inset，
不调整 contentOffset、回弹速度、惯性、frame、transform、玻璃材质或
低电量页，不添加滚动定时器 / 常驻任务。先前按用户要求去掉的两个
配套管理器安装入口继续保持去除。

## 验证与边界

- Windows 完整源码 / 契约回归 183 项通过，`git diff --check` 通过。
- 新增 `tests/test_rc9_table_backdrops.py --native` 并加入 macOS CI。
  直接抽取生产方法，使用 Foundation 与最小 view 顺序替身，
  检查三背景 / 三内容的全部 720 种排列、重复调用不重排、
  内容短 / 长、复用插入以及未挂载背景不被搬移。
- 该原生测试验证顺序算法，不运行 UIKit，不模拟 Preferences、
  摩擦 / 回弹物理、文字清晰度或 GPU 模糊。不得当作真机回弹验收。
- 新增原生回归、完整 TIPA 和包身份检查在提交后由 CI 执行。

真机应分别检查设置和关于：首次进入、慢拖顶部后松手、快速滑至顶部、
从底部返回顶部、来回进入子页、前后台切换后重复操作，以及底部完整显示
和文字清晰度。低电量页保持原状作为对照。

如果仍出现回弹不自然，需要记录实际表格的 frame / bounds、
contentOffset、contentInset / adjustedContentInset 和 contentSize
在拖动 / 松手 / 回弹阶段的变化，不能继续靠随意切换 inset、加空白或
修改模糊效果猜根因。本轮只确认并去除冗余层级重排，不声称已定位或
彻底解决设备上的回弹症状。
