本轮不再修改这部分。

“菜单行增加”只能说明内容长度、复用和显示回调的分布改变，
不能仅凭这一点确认回弹根因。设置标题由 `headerCellClass` 创建为
分组表头，不是普通第一行；玻璃代码中根据可见第一行类名跳过标题的
判断也不能据此认定为这次问题的原因。

## 本轮窄范围修正

旧 `willDisplayCell` 在每次显示任意一行时，都会对字典中的每个
玻璃 view 调用 `sendSubviewToBack:`，即便它们已经全部在内容后面。
多个玻璃 view 之间还会反复交换前后顺序。这是可从源码确认的额外操作；
低电量页没有对应的无条件循环。

在共用列表父类增加层级检查：

1. 遍历当前直接子 view，只检查所有已挂载玻璃是否连续位于内容后方。
2. 顺序已经正确时，不重排任何 view。
3. 确有内容被插入玻璃下方时，执行既有置底修正一次。
4. 不重排其他表格或已经移除的玻璃，不改变内容 view 的相对顺序。

设置 / 关于共享此检查。继续保留每行前景样式处理、背景初始化和真实遮挡
修正，避免简单删除置底保护后再次出现文字被玻璃采样而模糊的问题。

本轮不删除剩余菜单，不替换 Preferences，不增减顶部 / 底部 inset，
不调整 contentOffset、回弹速度、惯性、frame、transform、玻璃材质或
低电量页，不添加滚动定时器 / 常驻任务。先前按用户要求去掉的两个
配套管理器安装入口继续保持去除。

## 后续诊断包：仅记录，不宣称修复

在既有设置 / 关于返回箭头上增加手动长按入口，不增加菜单行，
低电量页不安装入口。默认关闭，不自动启用，也不改动现有滚动代理、
contentOffset、frame、inset、回弹、玻璃参数或越狱流程。

操作步骤：

1. 在设置页长按左上返回箭头约 0.8 秒，确认“已开启记录”。
2. 复现一次顶部重复回弹，松手并等回弹结束；尽量不要混入其他手势。
3. 再次长按返回箭头，使用原生分享面板导出 `RC9-scroll-*.json`。

确认弹窗后才待命，下一次表格拖动开始时才采样。最多记录 8 秒，
静止且无拖动 / 减速 0.5 秒则停止；离开页面或应用进入非活跃状态
立即停止并取消待命。固定 1024 条环形缓冲区，仅在导出时生成 JSON
和临时文件，不在每帧分配 JSON、写盘或打印日志，没有常驻后台任务。
每次新拖动覆盖上次记录，超过容量保留最新记录并在导出中报告丢弃数。

记录包括版本和构建提交、实际表格类、frame / bounds、页面大小、
contentOffset、contentSize、原始 / 自动调整 inset、安全区域、
拖动 / 减速状态，以及 Preferences 父类布局前后和 RC9 既有布局
完成后的阶段标记。它不截屏、不收集账号、注入配置或应用列表，
也不代替越狱详细日志。
