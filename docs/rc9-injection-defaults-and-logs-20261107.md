## 默认行为

配置均位于 jbroot 内 `/var/mobile/Library/RootHide/`：

| 文件 | 用途 | 是否单凭存在就开启用户白名单 |
| --- | --- | --- |
| `RootHideConfig.plist` | 官方黑名单 `appconfig`，RC9 另保留插件注入开关 | 否 |
| `cn.zqbb.inject.plist` | 用户注入白名单，同时充当模式选择文件 | 是 |
| `cn.zqbb.inject.system.plist` | 白名单模式下的系统进程放行配置 | 否 |
| `cn.zqbb.inject.wantsblacklist.plist` | 白名单模式下指定进程是否检查原黑名单 | 否 |
| `cn.zqbb.jetsam.addend.plist` | 每进程内存额度 | 否 |

因此，**首次干净环境在没有用户白名单文件时默认黑名单；覆盖安装保留已有模式**。
空字典、空文件或无效内容仍满足“文件存在”，不能因内容为空就判为黑名单。
不自动删除文件，否则会把用户主动启用的白名单及其配置一并重置。
“黑名单模式”也不等于无条件给所有系统进程注入，既有稳定性排除、
ProcessBlacklist、RootHide 应用名单和插件总开关仍各自生效。

RC9 的 `initializeRootHideWhitelistDefaults` 虽然名称中有 Whitelist，
只准备系统放行、特定进程黑名单覆盖及 Jetsam 配置，不创建用户模式文件。
该约定在历史提交 `b85e6b73` 引入初始化时已经存在；单凭群友描述不能
断言某次 RC9 升级自动打开了白名单。

## 安装入口与随包内容

- zqbb 设置中的 `Install Whitelist App` 调用 `installWhitelistAppPressed`，
  只打开 Sileo 中 `cn.zqbb.inject.manager` 的详情页，不直接创建名单或切换模式。
- 当前 RC9 设置中没有这个同名入口；本轮不擅自增加菜单，也不改动现有滚动布局。
- RC9 引导安装的 `roothideapp.deb` 是 `com.roothide.manager`
  `1.3.9+bindtrust1`，不是 `cn.zqbb.inject.manager`。
- 检查内置黑名单包及本地白名单参考包 `inject-3.2.1-5.deb` 的归档：
  安装脚本只有 uicache、所有者和 setuid 设置，没有写用户名单；
  payload 未包含用户模式 plist。这不证明白名单管理器启动后不会自行写配置。
- 内置 `bootstrap_1900.tar.zst` 共 6673 个成员，没有上述用户模式或
  RootHideConfig 配置；检查其中 23 个 `.sh` 及安装/卸载脚本，
  未匹配到相关配置名称。
  这不是对所有嵌套包、任意二进制动态行为的全面证明。

## 详细日志

官方、zqbb 与 RC9 都有 `Settings_Verbose_Logs` / `verboseLogsEnabled`：

- 默认关闭，只在未越狱时的设置中显示；越狱后看不到该开关并不表示被删掉。
- 开启后越狱按钮选用 `DODebugLogView`，而不是简略的 `DOLyricsLogView`。
- `startJailbreak` 启动应用 stdout/stderr 捕获，`sendLog` 把日志加入
  应用内 `logRecord`，再决定是否在简略界面过滤 debug 输出。
- `shareLogRecordFromView` 分享当前内存日志；它不是持久化的内核崩溃记录，
  不保证设备重启后仍可取回，也不是 `ENABLE_LOGS` 底层编译开关。
- 该选项本身不安装后台守护进程，也不让多巴胺为了日志常驻后台；
  不能宣传为无输出开销或已经覆盖全部运行时诊断。
- 现有应用日志没有明确输出用户模式文件是否存在；仅打开“详细日志”
  不能单独证明群友为何进入白名单模式。

## 本轮处理与待确认

本轮没有找到需要反转的默认值，故不强制切换或删除现有白名单。
新增 `tests/test_rc9_injection_defaults.py`，覆盖：

1. 初始化不创建、不删除用户模式文件；引导不默认安装白名单管理器。
2. 默认黑名单与已有白名单文件选择分支，包括空/无效内容。
3. 升级保留用户名单、显式 NO、Jetsam 和黑名单覆盖偏好。
4. 系统名单的一次迁移不反复补回用户删除项，损坏配置不被覆盖。
5. 详细日志的默认值、显示条件、调试界面及内存记录顺序保持不变。

本地项目 137 项回归通过；新增 Foundation 原生执行在写入时待 CI。
原生测试提取生产初始化和选择函数，以临时真实 plist 运行，
RootHide 路径映射及每进程决定用测试替身，不代替 iOS 注入验证。

群友问题还需实际安装包构建号、是否覆盖旧环境、是否启动/启用过白名单管理器，
以及设备上用户模式文件是否存在的只读证据。现阶段不能确定写入方，
不能把“可能是旧配置”写成已证实根因。
