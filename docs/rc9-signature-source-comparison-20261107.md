## 发现与修复

| 路径 | 固定官方 / ZQBB / RC9 原写法 | 本轮处理 |
| --- | --- | --- |
| `siginfo_resolve_superblob` 文件来源 | 用 `lseek/read` 读取，改变文件描述符共享偏移；只做一次读取 | 改为 `pread` 循环，接受正数短读并重试 `EINTR`；错误或未读完整时释放临时缓冲区 |
| 文件范围校验 | 先计算起点与终点，再与文件大小比较；加法可能溢出 | 拒绝负文件起点和负文件大小，以减法检查范围后再计算起点 |
| 本进程分配来源 | 未验证空指针就 `memcpy` | 空指针返回解析失败，释放本次分配 |
| `trust_signatures` 哈希计算 | 忽略 `csd_code_directory_calculate_hash` 返回值，可能把未写入的栈内容用于缓存查询/追加 | 失败时释放解码对象及临时数组，返回原有通用失败码 `-1`，不查询或追加信任缓存、不附加签名 |

上述是有代码依据的共同失败路径缺口，归类为 RC9 额外加固，不是逐字移植上游提交。
没有更换 ChOma 接口：哈希函数按已核实的 `int (..., void *)` 返回状态检查，
不改变成功时的哈希、信任或附加顺序。iOS 16 正常 PPL 路径会执行哈希检查；
现存 TXM 分支只增加同样的失败检查，没有移入新的 iOS 17+ 策略。

## 未关闭事项

当前 `systemwide_trust_file` 会重新从磁盘收集 `SIGNATURE_SOURCE_ALLOCATION`
签名，而不是把 dyldhook 传来的 FILE/PROC 描述直接交给 `trust_signatures`。
因此 FILE/PROC 读取测试是对保留接口的保护，不说明常规入口已实际触发这些故障。
哈希返回值检查覆盖当前收集后调用链；其失败不会撤销调用前已存在或已追加的信任缓存，
本轮没有引入跨函数事务或签名缓冲区回滚。

这不是完整签名解析器审计。ChOma 对 blob 内部长度、索引与结构的校验，
外部输入缓冲区实际容量、读取期间文件被同时改写的一致性，以及其他解析/附加
失败是否应改变现有“跳过”语义，仍需分别核实。本轮没有声称修复用户设备重启根因。

保持版本 `3.0.7`、最低 iOS `16.0` 与既有可越狱设备/系统范围；
不修改任何 UI、滚动、回弹、玻璃渲染、低电量计划、挂载或黑白名单默认值。
完整构建通过也不代替 iOS 16 各受支持组合的真机验收。
