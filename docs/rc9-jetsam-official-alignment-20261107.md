## 本次改动及边界

1. 只对设置客户端核实回复是字典、`result` 明确存在且为 INT64、
   数值在 C `int` 范围内；缺字段不再解释为成功。
2. GET 先初始化对象输出。失败不复制值；成功也必须有值。旧的 bool、
   uint64、double 便捷接口保留，但类型错误不会读取未初始化对象。
3. 新增保留状态码的 double 读取，以及 SET 后立即 GET 的核实入口。
   七档均为整数或半整数，比较不引入额外四舍五入。
4. Jetsam getter 不再主动把失败变成 30 MB；失败返回不可选的数值
   `-1`，保持 Preferences getter 的 NSNumber 类型。只有成功读取的
   默认值 0 使用推荐档位。现有说明页脚在读取失败时显示错误码。
5. setter 先核实运行值，再用检查错误的原子文件保存方法保存偏好。
   若运行值已应用但文件未保存，单独说明，不能声称设置完全没生效。
6. 新保存方法先写候选字典、成功后再发布内存偏好；其他设置继续使用
   原有 API，不整体重写偏好管理器。
7. 选择失败的刷新和提示延后到 Preferences 回调完成后，刷新当前
   Jetsam 选择页；不更改设置/关于的滚动与回弹代码。

设置客户端错误码：`-1` 无回复或服务端既有失败；`-2` 回复结构不合规；
`-3` 值缺失、类型或输入不合规；`-4` 写后回读与请求值不同。
没有新增 IPC 域、action 编号或权限豁免，也不假设任何一个错误已经
在用户设备上发生。无法回读时不自动重试或回写本地值，避免掩盖实际状态。

不改产品 3.0.7、最低 iOS 16.0、原有可越狱的 iOS 16 设备/固件组合、
Jetsam 的内存计算策略、低电量计划、挂载、注入默认策略或已删除菜单。
没有新增后台轮询；写后核实只发生在点选时。
