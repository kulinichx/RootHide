## 保留原版式的修正

保留对 `_table.frame` 重设代码的删除，同时在设置 / 关于外层使用
标准 UIViewController 容器，承接原来就存在的 12pt / 5pt 边距：

1. 原外层模态页面尺寸不变；容器只嵌入现有 `DOSettingsController`
   或 `DOCreditsViewController`，不重写 Preferences 数据 / 单元格 /
   点击动作，不增加可见菜单层级。
2. 子控制器的根 view 在原页面里保持 `CGRectInset(bounds, 12, 5)`，
   仅宽高随外层 autoresizing；列表在这个根 view 内继续由
   Preferences 填满。滚动时不再在两种 table 尺寸之间往返。
3. 以实测的 333 x 596.4 页面为例，对外的列表矩形仍为
   `[12, 5, 309, 586.4]`，不是宽 333 的列表；内层父类和 RC9
   使用同一个 309 x 586.4 viewport。
4. 外层承接原页面底色、圆角和裁剪；内层根 view 不重复圆角裁剪。
   原玻璃材质和层级保护不改，玻璃继续根据相同宽度的行矩形布局。
5. 返回箭头仍放在原外层 safe area 的 leading 10、top 6、44 x 44
   位置；边缘返回手势仍附着外层，不跟着列表内缩或滚动。
   状态栏样式和旋转策略由子控制器提供，出现 / 消失通知由 UIKit 自动转发。
6. 原首页和玻璃首页的四个设置 / 关于入口统一走这层承载；
   子页面仍使用原 UINavigationController。低电量等其他控制器
   不包裹、不改变其布局。
7. 共享列表仍调用父类，保留诊断阶段与相等判断保护的 24pt 底部余量。
   诊断可见性判断改为真实导航顶层容器，并记录外层 bounds 和
   列表在外层的矩形，便于后续直接核对边距，没有新增常驻采样。

旧的“frame 不同才赋值”不足以修复：真机表明父类每次已经先改成
页面尺寸，因此每次检查都会发现不同并再次缩表。

固定官方 RootHide `9617d75f` 的自有父类中也有 `12, 5, width-24,
height-10` 的 frame 赋值；本项是基于 RC9 真机记录主动删除的 UI
差异，不冒充从官方照搬的修复，也不声称官方设备行为与 RC9 相同。

这里把 RC9 边距移到容器拥有的子控制器根 view，而不是在滚动时
改 Preferences 拥有的 table。没有修改顶部 / 横向 contentInset，
没有缩放文字或改变控件尺寸。实际渲染、生命周期和子菜单导航仍须
真机验收，不能以几何公式等价替代 UIKit 验证。

核对了 Apple 官方容器文档的 addChild -> 嵌入根 view -> didMove
顺序、自动出现通知转发，以及 navigationController 查找最近导航
祖先的定义。参考：
`https://developer.apple.com/library/archive/featuredarticles/ViewControllerPGforiPhoneOS/ImplementingaContainerViewController.html`
与 `https://developer.apple.com/documentation/uikit/uiviewcontroller/navigationcontroller`。

不停止原生减速，不写 `contentOffset`，不关闭回弹，不禁用
高度估算，不增加定时布局，不改剩余菜单、授权检查、已验收的 Jetsam、
低电量界面 / 执行器、注入和越狱底层。版本继续 3.0.7，
只针对原有实际支持的 iOS 16 设备 / 固件组合。

设置 / 关于使用同一个父类，因此共同获得这项修改。
用户此次只提供设置页日志，不能把它说成关于页也已经取得运行时验证。
