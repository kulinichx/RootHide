# Jetsam 选择返回默认值排查

日期：2026-11-07。修前代码基线 `2a110d35e82bf839ae9f9630c8dfa9a2288e1b17`。

## 用户报告与边界

群友反馈：选择 30 MB 以外的 jetsam 选项，返回后又显示默认 30 MB。
本条反馈未提供群友的包编号、设备、是否已越狱和详细日志，不能套用
用户本人设置顶部回弹的 `1a7feb18` 包身份。尚未确认发生的是实际设置
未应用、实时读取失败，还是某个旧环境兼容问题。

## 确定的源码缺陷

`BaseBin/launchdhook/src/jbserver/jbdomain_systemwide.c` 的
`JBS_SYSTEMWIDE_JBSETTINGS_GET` 使用恰好两项的 `jbserver_arg[]`
复合字面量，但缺少 `{ 0 }` 结束项。真实分派器在参数名为空之前继续
读取，最多八个描述项；这个上限不代表两项数组之外可以安全读取。
因此第三项读取越界，属于可从源代码确定的未定义行为。

应用读取链为：

1. `readJetsamMultiplier:` 在已越狱状态查询实时 `jetsamMultiplier`。
2. `jbclient_jbsettings_get_double` 在没有成功取得值时返回 `0`。
3. UI 将小于 `1` 或 NaN 的值映射成选项 `6`，即推荐的 `+30 MB`。

这说明读取失败具有返回默认显示值的路径，但不能仅凭此认定实际值
已被重置，或已证明群友设备上的唯一触发原因。`0` 也代表既有运行时
默认策略，不能通过把 getter 无条件改成读取本地偏好来掩盖实时失败。

原 setter 还忽略实时设置返回码，并先持久化本地偏好，使失败也可能
被保存成用户已应用的选择。

## 固定上游对照

不将固定本地对象称为重新验证的远端最新版：

- 官方 RootHide `9617d75f476423fdfd33477299c8a1349eb6f375`：
  同处也是短复合数组且缺结束项，不能因官方存在就认为越界安全。
- ZQBB RootHide `7e14aa6155ce867e9052a88a8c17c632f4c30d77`：
  对应 GET 描述显式包含 `{ 0 }`，其结构还有内联参数数组的差异。
  RC9 只补自身指针数组的结束项，不整体替换协议或布局。
- 两个参考的 jetsam UI 仍采用选项除以二写入、乘二向上取整回读的
  映射；本次保留 RC9 原映射、默认推荐和各档位。

## 本轮修正

1. 只为实际 GET 参数表补上 `{ 0 }`，不改请求编号、权限、结构布局、
   分派槽数或运行时 jetsam 计算。
2. 已越狱时先检查实时 setter 的返回码；失败则不写入本地偏好，
   刷新父页面并从当前可见选择页提示错误码。
3. 未越狱时仍直接保存供下次越狱使用；实时 setter 成功才保存。
4. 不改 jetsam getter 的既有有效值 / 默认值处理，不用本地值冒充
   已应用的运行时值；不改低电量、注入默认策略或其他菜单。

## 安装与设备验收

参数表修正在 launchdhook 中。单纯覆盖安装应用不替换当前 launchd
里已经加载的旧代码；要验收此底层修正，需要用新包重启设备后重新越狱。
不保证本轮能解决尚待日志的 iPad 7 / iOS 16.6 landa 退出。

建议在相同环境逐个选择关闭、15、20、25、30、35、40 MB：
确认返回父页、重新进入、退出应用再打开后选择保持一致；
重新越狱后再次核对偏好加载。同时记录包编号、设备、系统版本及错误
提示。源码缺陷修复不等于群友反馈已获真机闭环。

产品保持 3.0.7，最低 iOS 16.0 和原来实际支持的 iOS 16
设备 / 固件组合不变。顶部回弹诊断能力保留，但仍不是回弹已修复。
