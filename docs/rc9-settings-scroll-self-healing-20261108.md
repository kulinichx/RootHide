## 确认的源码问题

设置 / 关于页的 `customGlassRefreshSectionBackdrops`、
`customGlassStyleVisibleCell` 以及 `willDisplayCell` 都会调用
`DORHSupporterIsVerified()`。前者由 `viewDidLayoutSubviews` 调用，
后两者会在单元格显示 / 复用时调用。

该函数进入 `DORHSupporterCurrentLicenseInfo()`：

1. 检查移除标记，读取授权候选，执行既有签名和设备校验。
2. 成功后调用 `DORHSupporterSetPersistentString`，即使文件中的授权
   与已验证值相同，也重新原子写入整个外部状态文件。
3. 即使 defaults 中已有同一授权，仍重复 `setObject` 和 `synchronize`。

因此，已激活设备上的一次普通 UI 刷新可触发不必要的同步持久化工作。
这从调用链和函数实现即可确认，不依赖推测私有 Preferences 的回弹算法。

低电量页也使用同一授权检查函数，只是调用分布不同。因此本发现不能
单独解释“只有设置 / 关于页顶部重复回弹”，也不能视作真机根因已定位。
本轮没有收到新的 `RC9-scroll-*.json`，实际几何变化仍缺少运行时证据。

## 本轮最小改动

- 非空字符串与当前外部状态中的值完全相同时，直接返回成功，不重写文件。
- defaults 已有同一已验证授权时，不重复设置与同步。
- 两份数据不一致、缺少副本或有效旧授权迁移时，继续执行原有自愈。
- 保留每次授权检查中的移除标记、候选读取和真实签名 / 设备校验，
  不缓存“已授权”布尔值，不新增授权绕过或失效延迟。
- 显式清除字符串的既有写入语义不变；真实写入失败不伪装成功，
  后续检查仍可再次尝试原有自愈。

该授权模块是 RC9 自有功能，固定官方 RootHide `9617d75f` 没有对应代码；
本项是 RC9 本地性能修正，不标为官方已有补丁的移植。
没有修改列表 frame、顶部 / 底部 inset、contentOffset、估算高度、
玻璃参数、菜单、低电量计划、越狱底层或 iOS 16 支持范围。
没有新增轮询、定时器或常驻后台工作。
