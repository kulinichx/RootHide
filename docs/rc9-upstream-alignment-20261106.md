# RC9 上游靠齐：第一阶段

## 方向

以官方 RootHide 为底层主基准，以 zqbb 的 RootHide 分支为补充参考，
把 RC9 自有功能尽量放入独立文件。先整理边界，再逐项跟进修复，
不整树覆盖，也不把产品版本改成 3.0.13 来代替实际移植。

本阶段从 `fad8bbbd6d8ef0b23a0b7d5d47d666243ae02182` 建立独立分支
`codex/rc9-upstream-alignment-20261106`。该起点已通过上一轮构建，
仍待真机验收，不标为稳定版。原工作区的未提交修改没有带入或覆盖。

## iOS 16 适配硬门槛

RC9 的适配目标是 **iOS 16 系列**。上游代码不会因为已发布就直接照搬：

- 不提高 RC9 的最低系统版本；App Debug/Release 与最终 TIPA 均保持 `16.0`。
- 只移植在 iOS 16 上可用、语义正确的修复；依赖 iOS 17 或更高版本的行为排除。
- 若较新 API 只是可选路径，必须有 iOS 16 可用的 fallback，并明确做 availability 检查。
- 每次比较都核验 API/ABI、系统结构和私有接口在 iOS 16 的实际条件。
- CI 通过不等于设备验收；在用户 iOS 16 设备上的验证单独记录。

## 本阶段改动

- 将低电量计划的三个应用端方法移入
  `Application/Dopamine/Jailbreak/DOEnvironmentManager+RCLowPowerSchedule.h/.m`。
- 从 `DOEnvironmentManager` 公共头和实现中移除这三个 RC9 专属接口；
  低电量页面改为显式导入扩展头，Xcode 应用目标单独编译扩展实现。
- 三个方法体与起点逐字一致；用 SHA-256 回归约束搬迁未改变逻辑。
- 新增针对真实扩展实现的 macOS 原生回归，覆盖越狱状态检查、
  参数拒绝、配置保存、Revision、状态读取、权限及写入成功才通知。
  系统边界由测试替身提供，不等同于 iOS 真机验证。
- 为独立整合分支接入现有 GitHub 完整构建流程，不改原候选分支。

这能减少以后合并官方环境管理代码时与 RC9 低电量功能的冲突，
但不代表整个环境管理器已经与上游完全一致。

## 第二阶段：自定义挂载模块

官方 `3.0.13-30` 与 zqbb 固定参考中都没有 RC9 的用户路径列表、
`newFakePath.plist` 持久化和设置页管理接口。zqbb 的 `fakelib` 挂载用于
启动及 userspace reboot 生命周期，是另一条内部机制，不替代 RC9 用户挂载。

- 将 RC9 自定义挂载 API 分离至
  `DOEnvironmentManager+RCFakeMounts.h/.m`，通用 EnvironmentManager 不再
  暴露这组 RC9 专属接口。
- 设置页和越狱完成恢复调用点显式导入扩展；行为、调用顺序、持久化格式、
  路径校验和 `jbctl` 参数均保持不变。
- 五个方法体按 SHA-256 与起点逐字核验；新增 macOS Foundation 原生 mock
  回归覆盖配置读写、权限边界、非法路径、实际命令参数、卸载失败不删镜像、
  成功卸载后删镜像及越狱完成时恢复。

## 保持不变

- 产品版本 3.0.7、iOS 16 范围、已有底层审计修复。
- 上游跟进严格遵守上面的 iOS 16 适配硬门槛，不以新版本号覆盖平台兼容性判断。
- 低电量配置格式、路径、权限、通知名称和保存时立即应用的语义。
- SpringBoard 的单次系统定时器；多巴胺应用不因此常驻后台。
  现有定时器允许系统按需唤醒，不能宣传为零耗电或零唤醒。
- 低电量页面布局、设置与关于页面、玻璃渲染和越狱流程。
- 飞行模式、Wi-Fi、数据联动仍未实现，不列为已完成功能。
