## iOS 16 适配硬门槛

RC9 的适配目标是 **RC9 3.0.7 越狱路径实际支持的全部 iOS 16.x 系统版本与设备组合**，不是只针对 iPadOS 16.5 或单一测试设备。上游代码不会因为已发布就直接照搬：

- 不提高 RC9 的最低系统版本；App Debug/Release 与最终 TIPA 均保持 `16.0`。
- 维护并逐项核对 RC9 可越狱的 iOS 16.x 版本、设备/芯片、漏洞与偏移组合；不得把 `MinimumOSVersion = 16.0` 当成整张越狱兼容矩阵已经通过验证。
- “全部 iOS 16 越狱版本”指 RC9 这条 3.0.7 RootHide 实现实际支持的版本/设备组合，不表示每个设备都能越狱每个 iOS 16.x 小版本；未盘点或未验证的组合必须明确标注。
- 只移植在 iOS 16 上可用、语义正确的修复；依赖 iOS 17 或更高版本的行为排除。
- 若较新 API 只是可选路径，必须有 iOS 16 可用的 fallback，并明确做 availability 检查。
- 每次比较都核验 API/ABI、系统结构和私有接口在 iOS 16 的实际条件。
- CI 通过不等于设备验收；在用户 iOS 16 设备上的验证单独记录。

当前完整版本/设备兼容矩阵仍待逐项盘点；构建成功和包内最低系统版本校验不替代该项工作。

- 将 RC9 自定义挂载 API 分离至
  `DOEnvironmentManager+RCFakeMounts.h/.m`，通用 EnvironmentManager 不再

  回归覆盖配置读写、权限边界、非法路径、实际命令参数、卸载失败不删镜像、
  成功卸载后删镜像及越狱完成时恢复。

### fork 握手

补充参考：ZQBB `c15b99798c64ee0c9004b5a7473d0adae0fe995c`。
官方固定参考仍是全局管道、不检查握手结果的实现；本项属于 ZQBB 补充修复，
不标成官方已有同一补丁。

- 每次调用拥有独立、初始化为 -1 的管道状态，不再相互覆盖全局描述符数组。
- 管道建立中途失败会释放已创建端点，向调用者返回错误，不直接 abort 父进程。
- 两个写端设置 Darwin `F_SETNOSIGPIPE`；父子分支先关闭各自不用的端点。
- 原始 read/write 包装将系统调用 carry 错误转换为负 errno；
  EINTR 重试，EOF 和其他失败不再当成握手完成。
- 只有子进程就绪且现有 Mach 权限修复成功，父进程才发送放行字节。
  失败时父进程终止并回收子进程，保存原始错误；
  子进程握手失败用原始 exit 退出，不运行未经修复的调用方代码。
- 保持现有 systemhook hook 安装和 Mach 消息协议，不引入新注入策略。

这不证明所有并发 fork 的继承端点生命周期或 fork 后配置锁已经解决；
后者仍为独立待审项，也没有把补丁认定为用户设备重启或 PPL 等待的根因修复。

### 签名散列收集

补充参考：ZQBB `15a075427c758eadd366260360c529a7762af4db` 中，
此前只移植过旧 arm64e 类型判定；本次补其适用的收集错误处理。

- 将“没有 LC_CODE_SIGNATURE / 非 adhoc，无需处理”与“读取、解析或计算散列失败”
  分开；后一种情况返回失败，不能再作为空集合成功。
- 通用 Fat 收集器改为有返回状态，修复直接覆盖 realloc 指针及未检查分配结果；
  通用、文件收集器都检查计数增长，失败时释放部分结果、保留空输出。
- 保留 RC9 文件路径过滤、TrollStore 判断、文件切片随机化及 errno 风格错误码。
  不照搬 ZQBB 的 TrollStoreLite/JailFools 策略或 Fat stream context 假设。
- 现有 systemwide trust、单文件 trustcache、更新 dyld 与命令行调用点已有错误检查，
  本次没有用上游整文件覆盖这些防护。
- 已对照 RC9 固定 ChOma `ed99ac526142e78a5bc99793cf433775040f9d67`
  的官方 `MachO.h`，确认 load-command 枚举接口返回 int，并使用原有 Blocks 回调签名。

本次不包含目录遍历的全部错误传播、签名附件所有路径、随机化回滚、
ChOma 解析器子模块更新或 trustcache 内核读者生命周期；不能标记整个签名信任链已关闭。

## 第四阶段：目录签名收集错误传播

日期：2026-11-07。沿用同一官方与 ZQBB 固定提交，不声称远端没有更新。
补充参考仍为 ZQBB `15a075427c758eadd366260360c529a7762af4db` 的
`trustcache_fs.c`；官方 `3.0.13-30` 在该文件中仍是没有返回状态的目录遍历。

### 已落实的代码

- 目录打开、读取、文件属性、内存分配、子目录及回调失败逐层返回错误，
  不再把遍历不完整当作空集合或成功。
- 读取 Mach-O/Fat 文件标记时重试 EINTR、支持短读并检查全部八种标记；
  普通资源、空文件和不足四字节的资源继续跳过，带完整标记但解析失败则报错。
- 失败时清理已收集的全部散列，不调用该次批量 trustcache 追加；
  单文件与目录入口在各条返回路径统一释放结果。
- 保留 RC9 的 errno 风格状态和 `file_collect_untrusted_cdhashes_by_path`
  调用，不替换为上游通用 Fat 收集器，避免绕过 RC9 路径过滤与逐切片随机化。
- 保持递归开关及不跟随符号链接、不处理设备/FIFO 等特殊文件的原有范围。
- 额外检查路径分配/长度、关闭失败及主错误优先级，不改变系统版本或私有接口。

### 回归范围与限制

- 新增 `tests/test_rc9_trustcache_directory.py`，接入现有 macOS 原生 CI。
  从生产文件提取五个函数，以真实主机目录、文件、符号链接及 FIFO，
  配合 I/O、分配、解析、收集和追加故障注入测试失败传播及清理。
- 本地 131 项项目回归及 `git diff --check` 通过；
  新原生执行和本阶段完整构建在本记录写入时待 CI 确认。
- ChOma 解析器、文件散列策略及内核追加在新增测试中仍为替身，
  既有文件策略另由 `test_rc9_signature_collection.py` 回归；
  不据此声称内核信任缓存的读者生命周期已经安全。
